# Domain docs

This repo is a single context.

- `GLOSSARY.md` at the root holds the domain language. Read it before you name a type, a module, a
  test or a ticket, and use its terms over their `_Avoid_` synonyms.
- `docs/adr/` holds the decisions that are hard to reverse, numbered `0001-…`. Read the ADRs in the
  area you are touching before you change it.
- `docs/research/` holds dated research notes. They are evidence for decisions, and the decision
  itself lives on the ticket or in an ADR.

When a term or a decision settles during a session, update `GLOSSARY.md` or add an ADR in the same
change, using the `domain-modeling` skill.
